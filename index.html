How to read this

  • Share of requests is the model's part of all requests that could be attributed to a model.
  • Requests per node per hour divides the model's requests by the number of nodes offering it: a rough proxy for what one more node offering the model could expect (the real share depends on the node's speed).
  • Output tokens per request shows how big a typical request is; it is not revenue (prompt tokens are not published).

Method and limits

  • Sampled once an hour. For each node the increase of its request and token counters since the previous sample is credited to its model: the only model it offers, or its current model when it offers several and that model did not change. Mixed nodes that switched model in between are skipped, so shares are an approximation (coverage is shown above).
  • Counters restart when a node restarts; a decrease is ignored for that node and hour.
  • "Nodes offering" counts connected nodes that advertise the model, whether or not they currently serve it.
  • Demand follows the clock and the week: a 24-hour window shows one day only.
